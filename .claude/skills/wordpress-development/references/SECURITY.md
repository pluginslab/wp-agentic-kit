# SECURITY.md

Mandatory security patterns for every plugin or feature generated by the wordpress-development skill. These rules are not negotiable — they are the price of admission to running on the open web.

## 1. ABSPATH guard on every PHP file

Every PHP file MUST start with:

```php
<?php
if ( ! defined( 'ABSPATH' ) ) {
    exit;
}
```

This prevents direct execution of plugin files via the web server.

## 2. Sanitize all input

Never trust `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, `$_SERVER['HTTP_*']`, REST request params, or any data from a database write that came from a user.

| Input type | Function |
|---|---|
| Plain text | `sanitize_text_field()` |
| Email | `sanitize_email()` |
| Integer | `absint()` |
| Slug / key | `sanitize_key()` |
| URL (storage) | `esc_url_raw()` |
| File name | `sanitize_file_name()` |
| Hex color | `sanitize_hex_color()` |
| HTML (allowed tags) | `wp_kses_post()` or `wp_kses( $value, $allowed )` |
| Textarea (preserve newlines) | `sanitize_textarea_field()` |
| Boolean | `(bool)` cast after `rest_sanitize_boolean()` |

```php
$name  = isset( $_POST['name'] )  ? sanitize_text_field( wp_unslash( $_POST['name'] ) ) : '';
$email = isset( $_POST['email'] ) ? sanitize_email( wp_unslash( $_POST['email'] ) ) : '';
$age   = isset( $_POST['age'] )   ? absint( $_POST['age'] ) : 0;
```

Note: `wp_unslash()` before sanitizing — WordPress slashes super-globals on load.

## 3. Escape all output

Never echo raw data. Pick the escape function that matches the context.

| Output context | Function |
|---|---|
| HTML body text | `esc_html()` |
| HTML attribute value | `esc_attr()` |
| URL in `href` / `src` | `esc_url()` |
| Inline JS data | `wp_json_encode()` |
| Trusted HTML | `wp_kses_post()` |
| Already-escaped translated string | `esc_html__()`, `esc_attr__()` |

```php
echo '<a href="' . esc_url( $url ) . '" title="' . esc_attr( $title ) . '">'
   . esc_html( $label ) . '</a>';
```

## 4. Verify nonces on every state-changing request

Forms:

```php
wp_nonce_field( 'acme_order_tracker_save_settings', '_acme_nonce' );

// On submit:
if ( ! isset( $_POST['_acme_nonce'] )
  || ! wp_verify_nonce( sanitize_text_field( wp_unslash( $_POST['_acme_nonce'] ) ),
                        'acme_order_tracker_save_settings' ) ) {
    wp_die( esc_html__( 'Security check failed.', 'acme-order-tracker' ) );
}
```

AJAX:

```php
check_ajax_referer( 'acme_order_tracker_ajax', '_ajax_nonce' );
```

REST: nonces flow through the `X-WP-Nonce` header automatically when using `wp.apiFetch`. Permission callbacks (below) still gate access.

## 5. Capability checks before any privileged action

```php
if ( ! current_user_can( 'manage_options' ) ) {
    wp_die( esc_html__( 'Insufficient permissions.', 'acme-order-tracker' ) );
}
```

REST permission callbacks:

```php
'permission_callback' => function () {
    return current_user_can( 'edit_posts' );
},
```

Never use `'permission_callback' => '__return_true'` for anything that mutates state or exposes private data.

## 6. Prepared queries — always

```php
global $wpdb;

$results = $wpdb->get_results(
    $wpdb->prepare(
        "SELECT * FROM {$wpdb->prefix}orders WHERE status = %s AND created_at > %s LIMIT %d",
        $status,
        $since,
        $limit
    )
);
```

Placeholders: `%s` string, `%d` integer, `%f` float. Never interpolate variables into the SQL string. Never concatenate user input into a query.

For table names that include user input (rare), validate against an allowlist of known table names before use.

## 7. File operations

- Validate file extensions and MIME types using `wp_check_filetype_and_ext()`.
- Use `wp_handle_upload()` for uploads — never roll your own move logic.
- Never include or require a file whose path comes from user input.
- Use `WP_Filesystem` for file writes when possible — it respects host restrictions.

## 8. Output to JS — encode, don't interpolate

Pass data from PHP to JS via `wp_localize_script()` or `wp_add_inline_script()` with `wp_json_encode()`:

```php
wp_localize_script(
    'acme-order-tracker-block',
    'acmeOrderTracker',
    [
        'apiUrl' => esc_url_raw( rest_url( 'acme-order-tracker/v1' ) ),
        'nonce'  => wp_create_nonce( 'wp_rest' ),
    ]
);
```

Never echo PHP variables directly inside `<script>` tags.

## 9. Forbidden constructs

- `eval()` — never. There is always another way.
- `extract()` — turns array keys into variables in scope. Hides bugs, security issues.
- `create_function()` — deprecated and dangerous.
- Variable variables (`$$var`) — opaque, error-prone.
- `unserialize()` on user data — use `wp_json_encode()` / `json_decode()` instead.
- `assert()` with a string argument — evaluated as PHP code.

## 10. Logging

- Never log sensitive data: passwords, tokens, full PII.
- Use `error_log()` only when `WP_DEBUG` and `WP_DEBUG_LOG` are on; gate it.
- For structured logging, push to a transient or custom table the user can clear.

## 11. Uninstall — leave no trace

`uninstall.php`:

```php
if ( ! defined( 'WP_UNINSTALL_PLUGIN' ) ) {
    exit;
}

delete_option( 'acme_order_tracker_options' );
delete_site_option( 'acme_order_tracker_options' );

// Drop custom tables, transients, user meta, post meta, scheduled events.
// Be exhaustive. Users who uninstall expect to be forgotten.
```

## 12. Defense in depth — habits

- One concern per function. Easier to audit.
- Return early on permission / nonce failures.
- Whitelist over blacklist. Define what's allowed, reject everything else.
- Treat every API surface — REST, AJAX, admin-post, custom — as untrusted.
- When in doubt, add a capability check.

## Quick self-audit before merging

- [ ] All PHP files start with the ABSPATH guard.
- [ ] No raw `$_GET`/`$_POST`/`$_REQUEST` reads without `wp_unslash()` + sanitizer.
- [ ] No `echo $var` without an escape function.
- [ ] Every form has `wp_nonce_field()` + `wp_verify_nonce()` on submit.
- [ ] Every AJAX endpoint has `check_ajax_referer()`.
- [ ] Every REST endpoint has a real `permission_callback`.
- [ ] Every admin action checks `current_user_can()`.
- [ ] Every database query that touches user input uses `$wpdb->prepare()`.
- [ ] No `eval`, `extract`, `create_function`, variable variables.
- [ ] `uninstall.php` removes all options, meta, tables, scheduled events.
